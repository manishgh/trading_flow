# TradingFlow candles and automatic support/resistance

14 November 2026 design, approved and implemented in stages from 15 November · Audit D1/D2 · Shared chart and Desk integration

## Desk workflow

Selecting a stock on Desk opens a chart in the existing stock detail panel. The chart defaults to **Intraday · 5m · regular session**. The user can select 1m or 15m for intraday detail or **Swing · 1d** for higher-timeframe context. Timeframe changes replace the chart subscription. Intraday zones stay on the 15m source across all three intraday views. Swing zones use daily bars. Swing daily candles show the last completed daily observation until the next verified daily observation arrives. A session filter can reveal premarket and postmarket candles when covered, with separate shading and labels. Add a weekly swing view after the daily source is verified. Overnight is a separate feed/session decision. These controls set the time and price context and carry no execution permissions.

Each candle and volume bar exposes the interval, OHLCV, source and receipt evidence. The chart shows feed, price basis, last completed bar age, and whether the selected series is streaming, delayed, repairing, history only, closed or unavailable. The nearest support and resistance bands have distinct labels and accessible text with range, confirmed pivot count, source timeframe, source dates and availability. The chart also offers previous-session and previous-week high/low, session VWAP and opening-range high/low when the inputs are available. The first Desk host supplies stored news and earnings records. A later host supplies recorded order, decision, entry, stop, target, fill and exit markers through the same chart interface. Marker details retain original timestamps, source and reason. An accessible OHLCV readout and overlay/marker list accompany the canvas.

### Five layers and default visibility

| Layer | First Desk checkpoint | Follow-on and evidence required |
|---|---|---|
| 1. Price and volume | Completed candles and volume, session shading, feed, basis and freshness always visible. A pending-close state covers the current incomplete interval. | Label and draw a distinct forming candle after the same-feed trade preview passes condition, revision and gap tests. |
| 2. Support, resistance and prior ranges | Show the closest bands and confirmed-reaction counts by default. Keep the previous regular day and week high/low behind one Prior ranges toggle on Intraday and use labelled daily source ranges on Swing. | Reuse the same band projection in other authorized hosts. |
| 3. Intraday context | Show bar-based regular-session VWAP and first 15-minute range by default when covered. Premarket high/low is an optional intraday line pair, available after the verified premarket window closes. | Add new session/feed choices only after they have coverage and pricing semantics. |
| 4. Higher timeframes | Swing defaults to daily candles. Offer SMA50 and SMA200 via one moving averages control, with signed distance in the details. | Add the weekly candle view and optional weekly average after verifying complete weekly input and warm-up. The rotation's recorded 210-session average belongs with the exact run evidence. |
| 5. Trades and events | Offer the same marker component for stored Desk news and earnings. Default to relevant visible-window markers and collapse overlaps into a count with a list. | Mount it in authorized order and strategy-run views with recorded entry, stop, target, actual fills, decisions and exits. Use shared VWAP/volume overlays and show their values at the selected bar. |

The selected candle details report the range, volume and available overlay distances. Price bands and chart overlays can be hidden individually. Give the strongest visual weight to candles, current volume and the nearest zones. Keep marker details in the list or on selection. A confirmed-reaction count records distinct confirmed pivots in the band and window and does not imply a number of profitable trades.

## Candle sources and clocks

- Treat `startUtc` as inclusive and `endUtc` as exclusive. Separately carry `sessionDate` and `segment` from the authoritative New York exchange calendar. Resolve session boundaries server-side, including DST, holidays and shortened sessions. Use actual exchange close for the chart's daily session completion check. Display New York time and expose exact UTC in details. Keep UTC sort keys, including when two local times would coincide. Missing calendar coverage leaves the affected session classification or overlay unavailable. For intraday derived bars use the existing `BarResampler` windows and require every expected interval to contain an accepted source minute or have authoritative no-qualifying-trades coverage. Keep an actual gap when coverage is unknown.
- For existing streamed symbols, start from canonical accepted 1m bars and their accepted revisions. Fan out immutable projection changes after canonical acceptance, with the matching ownership generation. Reserve time and capacity for canonical processing first. On uncovered history, read versions from the existing `market-state/shared/alpaca-sip` candle context and use a bounded same-feed history read where needed. REST `next_page_token` must be exhausted for a requested slice to claim complete retrieval. No strategy warm-up, discovery admission, new feed scope or new data root comes from selecting a row. If the selected symbol has only a Desk quote subscription, it is **History only · not streaming candles**, with a timestamp for the stored or fetched history. Do not upgrade quote activity to candle activity. Existing stream membership and per-symbol freshness are checked independently.
- Carry provider, feed, recorded adjustment policy, source kind, `knownAtUtc`, `retrievedAtUtc` when applicable, and a coverage watermark. Preserve actual ingest receipt for live bars. Historical REST may lack original receipt lineage, even with complete pagination. Keep original `knownAtUtc` null for those records and use completed batch retrieval as the chart's conservative availability time. The close of the bar does not establish when the server first saw it. For a derived bar use the maximum input availability, interval end, and time any coverage proof became available. If a stored row lacks original receipt, use the same conservative read-time basis with its assumption labelled. The chart can show ordinary historical prices across the covered window. Historical overlays derived from a later download carry the **Reconstructed from retrieved history** label. For observational SMA/VWAP curves only, the chart may draw a distinctly dashed retrospective calculation at the matched source candle close while preserving its later input availability separately. This does not assert that the value was available for a historical decision. The readout must say **Value reconstructed for this close** and show the actual availability time; missing source points and basis breaks cannot carry a preceding value forward. Support/resistance geometry and scalar reference ranges without retained historical versions remain current-only/right-edge annotations, not backdated historical activations. Use retained versions when showing past as-of state. Bind any reconstruction to the source retrieval or published reconstruction batch timestamp. A subsequent request for that same batch reuses the stamp.
- Current live parser tags SIP minute events `all`. The stream message itself has no adjustment option, and configured REST defaults to `all`. Keep those origin facts visible. A matching label alone does not prove compatible prices across a corporate action. At source joins use compatible provenance and reconcile the overlap. If a split, incompatible basis or conflicting overlap cannot be reconciled, isolate the segments and withhold any band or level that spans the break. Display a price-basis break and keep trade marker price/basis in its original evidence. Never join SIP and IEX into one series or compute SIP volume context from IEX. Swing uses the provider's separately labelled SIP daily series and aggregation basis, without mixing those daily highs/lows into an intraday regular-session level.
- Provisional intraday candles are a second step on the same socket. Add a bounded display-only aggregator for charted symbols to the existing trade dispatch. Validate SIP trade conditions separately for open/close, high/low and volume, deduplicate by provider trade identity, order by event time plus a deterministic tie-breaker, and handle cancels and corrections within a bounded interval. Keep the current bucket's data separate from `MarketBarEvent` and persisted completed history. Draw it as **Forming · trade preview**. Promotion happens only when the canonical completed version arrives. After missed preview messages, do not show a partly observed interval as a whole candle. Hide the preview until the next fully observed eligible bucket. After the clock passes bucket end with no accepted completed bar, show a pending close or a gap as appropriate. Derived 5m/15m previews may use covered accepted 1m constituents and the current 1m preview. Verify trade eligibility against provider reference fixtures before enabling OHLCV preview. The initial checkpoint can stream the canonical completed candles without an intraminute approximation. [Historical bars](https://docs.alpaca.markets/us/reference/stockbars) · [Alpaca bars and corrections](https://docs.alpaca.markets/us/docs/real-time-stock-pricing-data#bars)

## Support and resistance calculation

Propose a pure C# engine calculation in `TradingFlow.Engine/Indicators`. It accepts a versioned display profile, one chronological series of eligible completed bars, their effective availability and coverage, and the existing ATR14 values for that same series. It returns time-versioned bands and their evidence for a supplied cutoff. Web callers share the calculation and browser hosts render its output. Engine inputs and results have no ticket, order, broker, run selection or persistence dependency.

| Setting | Intraday | Swing |
|---|---|---|
| Pivot series | Regular-session 15m, scheduled session sequence | Completed SIP daily sessions |
| Left and right confirmation | 2 real completed bars on each side | 2 completed sessions on each side |
| Active pivot window | The current session and up to 5 preceding completed sessions, based on each pivot's confirmation session | The current session and up to 63 preceding completed sessions, based on each pivot's confirmation session |
| Initial display window | 5 sessions and the current session | 126 completed sessions, up to 252 in one view |
| Same-series ATR warm-up | Fixed trailing 120 genuine completed 15m bars through each confirmation, where coverage permits | Fixed trailing 120 genuine daily bars through each confirmation, where coverage permits |
| Display budget | Nearest 2 supports and 2 resistances, with any containing band counted against its type cap | Same |

The defaults are a versioned presentation profile. They express a starting level of visual detail and carry no estimate of predictive value. Changing zoom or 1m/5m/15m display interval does not change the calculation window, evidence or settings. Load enough pre-roll for the active-pivot window, right and left pivot inputs, and ATR before the first visible overlay point. For a maximum 252-session Swing view, 252 + 63 + 120 + 4 = 439 observations covers zone history. Cache the ATR input window result by its source-version watermark so browsing does not trigger repeated indicator work. If only current reconstructed overlays have evidence, past overlay pre-roll is unnecessary. If the required ATR warm-up or continuity is absent, show why fewer or no zones are available. Prior and next scheduled regular sessions can be adjacent for the pivot calculation, including across weekends. No-trade slots produce no pivot candidates. A documented no-qualifying-trades slot may be skipped. An unresolved gap splits the eligible sequence and calls for a fresh warm-up.

1. A pivot high must exceed the highs of the two eligible bars on each side. A pivot low must be below their lows. Equal extrema do not qualify in this version. A wide bar meeting both tests creates a high and a low pivot, evaluated in that predeclared order. A confirmation's source time is the end of the last right-hand bar. Its effective availability is the latest of that end, all input availability including ATR input and coverage, and the recorded acceptance or retrieval clock of any source change that supplied the result. The chart request and render clocks are separate. For contiguous 15m bars, a 10:00–10:15 New York pivot whose right candles end at 10:30 and 10:45 becomes available at 10:45 at the earliest. If the confirming bar is received at 10:46:03, the earliest effective time is 10:46:03. The pivot's location and the first instant a band may appear stay distinct.
2. Use decimal prices and ATR14 at confirmation, calculated using completed bars known at that time. A confirmed low proposes a support band centered on its low. A confirmed high proposes a resistance band centered on its high. Start with half-width `0.15 × ATR14`. Keep decimal bounds in the evidence and round only the display. Skip band creation when ATR is unavailable or nonpositive or when the proposed lower price is nonpositive. Seed an immutable band ID from profile, series, type and first contributing pivot key.
3. On an eligible completed event, accepted revision, or exchange-session expiry, rebuild only the bounded active pivot set in confirmation order. Resolve simultaneous pivots by source time, high before low, then stable pivot key. An active pivot can join a band of the same type when its price lies within `0.35 × ATR14` of the band's first pivot price and the union of the old and proposed bands spans at most `0.75 × ATR14` at confirmation. Choose the closest eligible first pivot price, then earliest confirmation, then stable band ID. Anchoring to the first eligible pivot and the union cap prevent a chain of nearby pivots joining distant prices. Dedup by logical pivot key. Publish only projection differences, with immutable version timestamps. A pivot reaching the end of its window leaves the set. Re-clustering can shrink a band, retire it or give its remaining constituents a new first pivot and band ID. There is no older hidden anchor to restore after reconnect. Role flips and tests of how often price held are outside this version.
4. Render versions from their effective timestamp to the next version or expiry, clipped to the loaded view. Current annotations choose bands on the correct side of the latest eligible completed close or containing it. For each type, rank by distance to the nearest edge (zero when inside), then newest contributing confirmation and stable ID. Label a containing band **Price in band**. When price crosses a whole band the selection can drop it at the next completed close, without changing its type or sending an alert or order. The renderer exposes count and age as observations. It gives no probability, pass/fail signal, or suggested stop.
5. A canonical revision can change a pivot, zone or ATR only once the revision is known. Recompute affected inputs and the bounded active set. Publish the changed bands or removals with the revision's availability. A confirmed pivot removed by a revision retracts its current contribution at that time. Preserve emitted historical segments where their version and availability are known. After loss of chart projection, reconstruct only from available source versions or show the current reconstruction with a coverage label. Keep the last good view marked stale during repair. The calculation can be reused for future research if separately authorized, with frozen inputs and its own deterministic replay acceptance. This proposal provides no rule for support-break exits, stop movement, sizing or order admission.

For a check on the clustering rule, with ATR14 of 2.00 and a support pivot of 100.00, start at 99.70–100.30. A 100.45 pivot joins at the same ATR, expanding the range to 99.70–100.75. A 100.90 pivot cannot join this band because its distance from 100.00 is 0.90, above 0.70, even though it is close to the second pivot.

## Other overlays and markers

- Intraday previous session and previous week use covered completed regular-session intervals and the same chart price basis. Previous week means the preceding New York Monday–Sunday calendar week, using its actual scheduled sessions. Swing uses complete daily bars with their provider aggregation label. High and low become available after the last required constituent is completed and observed. Require coverage for the whole period and suppress the level when there is no price evidence for the range. Holiday weeks and shortened closes follow the calendar.
- Use the existing typical-price-times-volume VWAP on completed regular-session minutes, resetting at each regular open. Reuse the existing math with RTH-filtered inputs, as the current method resets by New York date and includes whatever bars it receives. Carry the description **Bar-based RTH VWAP**. A data gap that leaves cumulative volume unverified removes the line until reconciled.
- Premarket high/low uses covered premarket intervals in the scheduled New York premarket window, 04:00 to the regular open for the supported feed. Draw the line pair once the whole window has closed and been observed. If one edge lacks coverage, a partial range can remain in the candle view with its gap. It cannot supply the completed premarket overlay.
- The **First 15m high/low** reflects the first completed regular 15 minutes with the requisite price and coverage, based on the existing opening-window validation. It becomes available at or after OR completion as observed. It does not invoke the ORB decision process. Later page hosts can add exact strategy lines from recorded decisions, with strategy identity and timestamp.
- Swing moving averages reuse the existing completed daily SIP SMA50 and SMA200 series and require uninterrupted compatible basis and a full period. Show signed percentage distance as 100 × (latest eligible completed close ÷ average − 1). Use the same convention for daily and optional weekly levels and state which close and level were used. The follow-on weekly view groups verified daily observations by New York Monday–Sunday week, closes at the last scheduled session's close, and waits for all required constituents and coverage. Keep daily zones as the default structural context across the Swing views. Offer a 40-week simple average only with 40 genuine completed weeks. Weekly grouping requires a small shared projection because `BarResampler` currently uses a daily bucket for every interval of a day or longer. Up to 550 daily observations provides sufficient input for 52 displayed weeks with a 40-week average, including calendar slack. A run can show its own exact recorded moving average independently of the generic chart defaults.
- Use existing authorized record projections for markers. Use a news publication or scheduled event time as the event's displayed time, with original ingestion, schedule receipt, and release details shown separately. An estimated earnings schedule is labelled as an estimate. Order and fill markers require an exact authorized run or account selection server-side, and their original known times. Draw planned entry, working stop and target only across their recorded effective intervals. Show submitted or working orders and fills with explicit state and distinguish actual fills from planned prices. Include actual quantity, price, time and reason when recorded. If a contextual VWAP or volume value is shown beside a marker, require a compatible completed input and retain its availability clock. Markers between candles or in a closed period preserve their time and show in the list even if they lack a same-interval bar. They cannot create a candle or past trading evidence. Keep symbol-only price responses free of private account or run records.

## WebSocket contract, history and limits

Use a same-origin authenticated ASP.NET Core SignalR hub at proposed `/api/v1/charts/hub`, configured for WebSockets. Keep a versioned read-only chart history route for bounded earlier pages. A shared `ChartSeriesService` owns snapshots, projected changes and history queries. Charts subscribe to an allowlisted series key including canonical equity symbol, interval, session view and expected feed/basis chosen server-side. An authorized Desk scope or authorized host context validates membership. A SignalR connection hosts one active Desk view, with the reusable contract capped at four series keys per connection for future page use. Row selection cancels the prior load and swaps its subscription; discard late frames from the previous selection. [Microsoft WebSockets](https://learn.microsoft.com/aspnet/core/fundamentals/websockets) · [SignalR security](https://learn.microsoft.com/aspnet/core/signalr/security) · [SignalR configuration](https://learn.microsoft.com/aspnet/core/signalr/configuration)

**Snapshot and update contract.** Send `contractVersion`, `seriesKey`, `epoch`, per-series `sequence`, `asOfUtc`, status and reason, provenance and coverage, ordered bars, initial overlays, and a bounded opaque history cursor when available. Bars include OHLCV, interval, completion state and source clocks. Bands and reference levels carry the profile/source and both the calculation clock and effective availability. Deliver typed messages for completed upsert, revision, optional preview, overlay upsert/removal, heartbeat/status, and reset. Use the same bar key for a preview, completed bar and its revisions so the browser replaces the right point. Capture sequence and subscribe atomically against one projection. Buffer the bounded updates arriving during snapshot transfer and send them after the baseline. History requests are for older points from the same validated series, with cursor and coverage dates. Display overlapping archived items idempotently. Keep the current request generation separate from the server epoch.

**Disconnect and repair.** Show the last update time and source age during reconnect. A client may resume only with the same authorized series and epoch when the entire sequence suffix remains buffered. A mismatch, replacement owner, expired cursor, ambiguous revision or slow-reader overflow sends a reset when possible and requires a new baseline. Reconnect with bounded exponential backoff and jitter. A heartbeat proves the browser-to-server path. Symbol status and coverage come from the provider subscription state, session schedule and time of the latest eligible bar. During an active expected intraday segment apply the existing configurable active-source staleness threshold (3 minutes by default) to source 1m coverage or receipt and known quiet or halted intervals. The age of a 15m bar alone is not a freshness failure. For daily and weekly contexts use the next scheduled observation due and a configured grace period, with an independent underlying connection status. Keep an explicit no-new-bar state for verified quiet intervals and a separate closed state. Provider lease loss or disconnect immediately suppresses the live claim and provisional data. Canonical recovery can fill gaps before the chart returns to streaming.

**Initial ceilings to verify under load.** One active Desk chart, four series per connection, two connections per authenticated user and 32 shared active series entries per process. Cap each initial or paged series response at 500 bars and 256 KiB using chunked snapshot framing if needed. For 1m views fetch up to one regular session at a time. For derived intraday history constrain each seed/backfill to at most 15 calendar-authorized trading sessions (including previous-week context) and 16,000 source minutes. For daily history constrain acquisition to at most 500 observations, inclusive of pre-roll for the zone and SMA200 windows, and chart history to 252. A weekly request in a later checkpoint can raise its own acquisition ceiling to 550 daily observations without widening the daily response. Fix warm-up and evaluation windows server-side for a given profile and cutoff. Allow up to 100 markers per viewport response. Coalesce identical history requests under a shared budget of two concurrent loads, short request deadlines and a bounded queue. Idle entries evict from the in-memory projection only. Aim for at most one preview per series per second. Limit replay to 128 frames and 128 KiB per active series, with at most 32 frames or 64 KiB queued per subscriber. Coalesce only replaceable previews and heartbeats before assigning a delivered update sequence. On missing a completed update, reset that subscriber. Measure and bound serialization, allocations, provider request counts, archive work, chart history latency and overflow. Tune these ceilings in the scoped load test before rollout.

**Security and scope.** Require the same relevant authenticated page policy for both WebSocket and HTTP. Validate the WebSocket Origin against the configured app origin and use the existing same-origin session over TLS, without credentials in query strings. Recheck authorization on subscribe/history, restrict each cursor to the authorized series and expiry, enforce auth lifetime/disconnect, and cap new connections, subscription changes and input bytes including upgraded connections. Validate symbols through the existing canonical Alpaca mapper and server-side allowed membership, and accept only declared intervals/session views. Deny arbitrary URLs, wildcards, cross-user run access and unbounded date requests. Serve pinned browser assets locally with the project CSP and retain notices. Card text uses escaped rendering. There is no client provider credential, provider subscription mutation, data migration or new archive writer in the first checkpoint. Normal REST use follows the existing adapter's archival requirements. Verify SIP entitlement for the intended authenticated deployment before enabling an audience beyond the operator.

## Chart dependency decision

Recommend approval of a pinned TradingView Lightweight Charts 5.x release. The official docs show candlestick, histogram, multi-pane, series marker and primitive APIs that fit the shared renderer. A bounded price-band primitive can render the server's zone versions and session shading. ## Proposed checkpoints and acceptance

1. **Completed candles and initial Desk overlays, medium component change.** Add a bounded projection seam to Engine and its market-state service, chart DTOs in `TradingFlow.Contracts/V1`, an authorized hub and history route under `TradingFlow.Web`, and one Desk-mounted chart module under `wwwroot`. Add the pure indicator with explicit display parameter profile. Reuse existing repositories for Desk events. Test fixture bars through existing provider/store interfaces and swap the browser adapter in offline UI tests. Approval includes the WebSocket client asset and one chart package with notices. The first checkpoint excludes new market subscriptions and data migrations.
2. **Forming trade preview, separate focused component checkpoint.** Add conditions, correction/cancel handling, continuity and bounded memory tests around a display tap in the existing Alpaca receiver. Gate preview on fixture coverage and current subscription. Keep the same DTO and no additional provider socket. Remaining decision is exact condition handling for price and volume when provider test cases disagree with our calculation. Until then, show a forming-state placeholder. The forming-candle layer is complete only when a distinct preview is rendered from fully observed eligible trades and the provider fixture tests pass for trade conditions, deduplication, correction and cancellation, and missed data or reconnect during an interval.
3. **Weekly Swing view and additional page hosts, separately scoped.** Add the verified weekly projection and optional average. Reuse the series and chart adapter for strategy run, orders, news and earnings. Backtest review loads intentionally captured bars and exact run markers with their persisted clocks and run permissions, via an explicitly separate historical source binding. Align navigation or expand supported symbols only by separately approved design. The current recommendation is to keep Desk selection observational. Count the trade message tap, dependency choice and any future change to per-symbol provider subscriptions as explicit review decisions.

The user approved the first checkpoint and prioritized a common reusable chart, responsive plotting and usability. ### Fable follow-up and real-data acceptance, 15 November

Current zones remain at the right edge, with readable Support/Resistance labels, exact ranges and 15m/daily source context in an always-visible legend. The mobile price grid gives numeric values enough width without wrapping digits. Candle evidence names New York, Berlin and UTC clocks. An expired earlier-page cursor offers a same-view history reload without hiding the current candles.

The default authenticated chart connection allowance is four per user. ChartTransport:MaximumConnectionsPerUser can be configured from one through eight, retaining the 128 process-wide cap and per-user request budget. This permits Desk plus multiple chart tabs without unbounded fanout.

History refresh reuses verified settled sessions across nearby date rollovers. Active requests fetch a bounded 15-minute overlap, with periodic full-session revision checks and explicit final-close verification. Empty or incomplete evidence cannot advance coverage; failed daily probes retry at the normal cache interval. Noncontiguous missing-date repair retains all completed rows in the fetched span, preventing false interior price-basis breaks. Original archives are never deleted or overwritten. Cold starts, cache eviction, genuine new periods, revisions and unresolved gaps may acquire new evidence.

Reference overlays use the latest visible candle session for both daily and intraday displays; actual cutoff/receipt clocks still control availability and freshness. A Sunday chart of Friday candles therefore shows Friday VWAP/opening/premarket and Thursday prior-session levels, with market-closed status.
