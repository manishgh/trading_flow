## Forming candle preview

Use trades already dispatched by the leased SIP connection for tracked market-state symbols. `AlpacaStreamClient.SubscribeMarketStateAsync` already requests trades. `AlpacaMarketStateStreamService.ReceiveMessagesAsync` currently handles quotes, canonical bars and status, without a forming trade projection. Add a display-only consumer behind the same connection fence, acknowledged symbol generation and verified session schedule. A chart watch must not change the upstream subscriptions or open a second connection. A symbol with stored history or display quotes only remains “Not streaming” for candles.

- Offer `1m`, `5m` and `15m` for the current regular or extended segment. Start qualifying trade coverage at the first full minute boundary after the symbol subscription is acknowledged, warmed and reconciled. Restart that rule after disconnect, repair or lost coverage. Use event time for bucket membership and actual receipt time for the display’s observation clock. Clip the bucket at the verified segment end. For 5m or 15m, combine authoritative completed minute children with the current eligible trade subtotal, replacing the minute subtotal when its bar is confirmed. A quiet earlier interval counts only with canonical no-trade proof. Socket silence establishes neither coverage nor a candle. If any earlier portion is unknown, wait for a covered bucket.
- Enable the preview only after capturing and reviewing the exact SIP condition and correction rules for open, high, low, close and volume. The archived `SipReviewedConditionPolicy` covers ordinary research prints and does not establish those field rules. Use event order with a stable provider tie-breaker and deduplicate exact messages. Apply identifiable cancellations and corrections within the open minute. With an unresolved identity, condition or correction, clear the affected preview and any current larger bucket the message could affect until canonical reconciliation proves the affected child. Show eligible volume only where its inclusion is proved. A quiet healthy stream retains its true last observation time.
- Retain only the current minute’s trade IDs and aggregate state per already tracked symbol, with proposed ceilings of 10,000 distinct events per symbol and 100,000 across the connection. Overflow makes the affected minute’s preview unavailable. Reuse the existing canonical minute read for the rest of the bucket. When a previous minute is awaiting its confirmed bar, suppress a larger-bucket preview until that child is covered. Remove state on lease loss, generation change or symbol removal. No new durable store, history crawl or client-accessible trade tape.
- Pass the Layers opt-in as watch options alongside the unchanged `ChartSeriesKey`. The existing completed watch, cursor, source reads, cache keys and fingerprints use the same canonical key and schedule for either setting. On the same watch, send at most one separate 2 KiB preview frame per existing five-second tick, including status/clear frames. Deduplicate on bucket identity, coverage status, values and source event/receipt clocks. Use neither the watch clock nor the snapshot fingerprint to manufacture updates. Attach the active watch epoch, latest completed baseline sequence and a separate monotonic preview sequence. Discard superseded watch, baseline and preview sequences on the client. Preview frames follow the complete baseline or heartbeat for their tick and cannot advance the candle history cursor.
- Return feed, bucket identity and times, OHLC, eligible volume if available, last event and observation clocks, and status. Render a separate outlined candle with “Forming · SIP”. Clear it on verified completion, suppression, or context change. Hold the selected completed candle and its evidence fixed. Keep the preview out of historical payloads and study inputs. Strategies, alerts, indicators, zones, fills and replay continue to consume confirmed inputs.

Affected paths are the Alpaca market-message parser, `AlpacaMarketStateStreamService`, Web Charts projection and `StockChartHub`, `ChartContracts`, and the shared chart controls, transport and plot. Keep tests independent of the operator host. Replay synthetic SIP frames for out-of-order trades, duplicate identities, corrections, quiet/unknown coverage, partial segment ends, minute replacement, fence races, stale connection and overflow. Compare completed snapshots, study values, canonical read counts, cursor keys and strategy inputs with preview on and off. Browser tests cover frame deduplication and rejection, selection stability, verified completion, unsupported states and paging.

`RuntimeHostedServiceRegistration` starts the candle SIP service only with the runtime enabled. A paused host can have separate news/earnings feeds while the candle stream stays unavailable. Real-data acceptance can observe only an already authorized, attended, runtime-enabled SIP session, with its approved symbols, window and entry gates intact. Match an eligible captured trade to the preview and the confirmed bar to the completed candle. Preserve the source receipts and clocks. Keep acceptance pending without such a session. Approval of this chart layer grants no runtime, account, subscription or order authority.

## Private paper order evidence

Add the existing chart to a selected symbol on Paper run detail and to a selected order/position on Orders. Show the resolved paper profile, run, symbol and selected order or position context with a link to the underlying detail. News and earnings continue to come from the existing public-market marker projection. A public symbol chart, including Desk, receives the existing market data only.

- `TradingFlowRoles.Administrator` is an existing app role. `BrokerAccountBindingOptions` pins one expected broker account. Neither establishes an operator-to-paper-run grant today. Add a chart-read-only, empty-by-default server configuration allowlist with the local Identity user GUID, exact expected paper account ID, and explicit allowed durable paper job IDs and standalone manual intent IDs. The host operator maintains these grants in protected local configuration. No wildcard, implicit account owner, new admin screen or database table is needed. Require the user’s current Administrator membership from Identity and the active exact grant at issuance and every read. Removing a grant through the host configuration or removing the role from Identity invalidates existing contexts on the next request after the change takes effect. Configuration that requires a host restart takes effect on restart.
- Issue a short-lived opaque Data Protection token only after the Paper or Orders server page resolves a permitted selection. Bind its purpose, user GUID, paper account, originating run or standalone intent, canonical symbol, selected order or generation, and expiry. Use a separate purpose from market history cursors. The same-origin authenticated endpoint validates the token and rechecks the active role, grant and durable bindings each time, including paging. For a run, require a persisted job of type `paper`, an agreeing durable paper `ProductionRun`, and a matching persisted originating intent for the selected order or generation. For a standalone manual order, require an exactly allowed, persisted manual intent with verifiable provenance and matching durable paper profile. Paper mode and account must match the server’s enforced expected binding and the durable intent account. Derive scope from stored evidence. Inconsistent, missing, legacy-unknown, live and simulated contexts are denied with the same unavailable response. The token and ordinary chart symbol permission confer no account authority.
- For an authorized position generation, prove the opening ledger event and originating intent by exact account, symbol, generation and run. Then use the relation in `AuditWorkflowReader` to include close events bearing the same account, symbol and generation even if a separate reconciliation run recorded them. Include protection or replacement owner records only with the same proven generation and exact order/owner linkage. Join selected-order events through their own durable intent and lifecycle IDs. A standalone manual intent grant covers that order only. A manual position context can show only the generation proven to originate from that allowed intent. Missing links leave the related evidence unavailable.
- Resolve context before querying the durable journal for frozen strategy plan/decision evidence, `OrderIntentRecord`, broker lifecycle `OrderEventRecord` and verified protection/replacement records. Reuse `PaperExecutionComparison.ReadUnitFills` on records scoped to the context. Opening a layer uses durable local reads and never queries the broker, places an order or changes protection.
- Show a decision at its recorded time and available reason. Label planned and broker-effective entry, stop and target separately with their verified start and end times. Replacements end the earlier effective span on verified transition evidence. Cancellations or missing protection remain legible. Use the actual execution ID, time, raw price and incremental quantity for each partial entry or exit. Include the durable reason when available. If time is absent, keep the record in details without placing a marker at a guessed time. Preserve exact time when visually grouped by candle. The chart’s SIP basis is adjusted `all`. Plot a broker price only when a verified transform to the selected segment’s chart basis is available. Initially use time markers and raw-price details wherever that proof is absent, including basis gaps, and show “Price overlay unavailable” at the relevant evidence. Do not introduce a raw series or request for this layer.
- Accept a half-open UTC window of at most 31 days (744 elapsed hours) with an end at or before the server clock. Reject oversize or reversed ranges before the journal read. For a wider chart view, ask the operator to narrow the range for private evidence.
- Use indexed equality seeks by the exact permitted identity. Position events and linked intents use account, symbol and generation indexes. Order lifecycle uses the resolved client order ID index. Replacement records use the verified account and broker order/root index. Apply SQL limits with an overall 200-candidate budget and one overflow sentinel across the scoped reads, before decoding payloads or resolving further links. Use only the required journal columns. Compare stored UTC instants and select the preceding verified effective state per level within this bounded set, avoiding SQLite ordering or filtering on `DateTimeOffset` text. Confirm indexed seeks and the absence of an unbounded sort with query-plan tests. If a generation exceeds the read budget, report incomplete evidence and offer a permitted exact-order view.
- Return at most 100 visible events plus the latest verified active entry, stop and target, ordered by timestamp and stable ID. Show when the output is truncated. Reuse chart request limits and cancel an outdated request on symbol/context/view change. Return `Cache-Control: no-store`. Keep results out of shared chart snapshots, cursor tokens for public history, shared caches and client storage. Drop the in-memory layer on context or authentication change. Render selection and freshness separately from market data.

Affected paths are `PaperJob` and `Orders` page models/views, the new chart policy/configuration wiring, private endpoint and scoped local journal projection, and shared Layers, plotting and evidence rendering. Test role and grant removal with an issued token, cross-account/profile/run/symbol denial, standalone chart isolation, unrelated manual orders, same-generation cross-run closes and protection replacements, duplicated partial fills, adjusted-price suppression, UTC window limits, bounded overflow on a large journal, expiry, paging, context switches and zero broker commands. Reconcile existing, authorized paper evidence by execution ID, raw price, quantity and clock. Leave acceptance pending for missing facts. Chart approval grants no new paper execution operation.

## Weekly candles

Add a `1w` chart option alongside `1d`. Aggregate current verified native SIP daily candles on their existing adjusted `all` basis. Label the source “SIP daily · adjusted” and use the exchange calendar for weekly grouping and availability. The regular close sets the earliest completion clock. Source OHLCV retains the provider daily series’ session semantics. Use exchange-local Monday–Sunday for grouping, with the first and last scheduled trading session dates as the visible bar label. The key is the first session date and the end is the actual regular close of the last session. Read the verified schedule through the week’s end before determining its last trading day. This handles holidays, early closes and DST. A whole week with no scheduled sessions has no candle.

- Aggregate the first open, maximum high, minimum low, last close and total volume from the required daily candles. A missing or conflicting session, unverified calendar, unavailable constituent or internal price-basis break omits the affected week and reports a coverage gap. The current unfinished week stays pending. Availability is the latest of the final scheduled close and the constituents’ availability. Carry source and reconstruction evidence into the weekly bar. A late correction revises derived history through the existing chart revision path. Readouts show literal exchange dates and daily/weekly units explicitly.
- Give `1w` an explicit display and pager branch through `ChartBarProjector`, `ChartSeriesService`, `ChartHistorySource` and the history cursor. The newest page shows the last 100 or fewer whole eligible weeks from the bounded 500-session daily source, bypassing the intraday viewport default. Skip any week cut by the lower acquisition edge before identifying the earliest evaluated week. The cursor is the first scheduled session of that earliest fully evaluated week, or the earliest returned week if the 100-week ceiling is reached. The next page reads strictly before the cursor to fetch the skipped edge week whole under the same daily limit. Preserve omitted-week coverage and allow a following cursor when a page has gaps. Keep daily and calendar revisions in projection identity. Reuse the existing daily source and transport limits.
- The initial weekly view displays candles, volume and existing news/earnings events, grouped to a week with original event clocks in details. Disable the study and structural overlay controls on `1w` with their availability explanation. Returning to daily or intraday restores the previous controls and their named calculation intervals. Weekly-specific indicators, pivots, forming weeks and private overlays on weekly candles remain outside this increment.

Use holiday-shortened, DST, early-close, missing-session, split, correction and reconstruction synthetic cases. Test a two-page rollover where the acquisition edge cuts a week and the next exclusive-before page returns that whole week exactly once. Browser tests exercise date labels, event time, indicator availability and the unchanged daily and intraday controls. For real-data acceptance, reconcile a normal and a shortened week to every constituent SIP daily receipt and the archived exchange calendar, with a basis-break case if retained evidence exists. Check the unfinished week’s pending status while the exchange is open. Avoid research holdout partitions.

## Volume profile remains optional

Daily or minute OHLCV contains one volume total per candle. It cannot support a volume-at-price distribution. Revisit one completed regular session per symbol only if authorized historical SIP trade prints have full time and pagination coverage, retained source receipts, exact price and size, reviewed inclusion rules, and a verified corrections/cancellations policy. Start with retained evidence via `SipExecutionArchiveReader` and `SipReviewedConditionPolicy`. Have the next proposal show their suitability for this particular display. Do not trigger new capture, purchase or feed traffic from the chart.

That later proposal must specify fixed price-bin boundaries, an event and byte ceiling, retry/cancel behavior and a bounded cache keyed to the verified evidence revision and bin scheme. A partial archive, unresolved correction or exceeded ceiling yields “Volume profile unavailable”. Acceptance would reconcile the bin sum and sample price levels to exact retained prints. No volume profile UI, approximation or new dependency is included for approval here.
